# Lab safety and publication checklist

Spider-Sense is an authorized personal learning environment. Before publishing an artifact:

- [ ] Remove credentials, tokens, private keys, cookies, and authentication headers.
- [ ] Replace public/private IP addresses, MAC addresses, hostnames, usernames, and domain names when disclosure is unnecessary.
- [ ] Remove personal data and third-party identifiers from packet captures and logs.
- [ ] Confirm screenshots do not expose dashboards, API tokens, endpoints, or browser sessions that should remain private.
- [ ] Clearly distinguish synthetic test events from real observations.
- [ ] Keep any exploitation or active scanning within systems you own or are authorized to test.
- [ ] Verify instructions do not assume that Suricata sees all traffic on the LAN.
- [ ] Document tool versions, configuration assumptions, and evidence limitations.

**Publication principle:** Evidence supports claims. If a result cannot be verified, label it as a goal, hypothesis, or planned improvement.
